# PRD: Bug Fix - Fel portfölj sparas vid email-uppdatering

## Problem Description

When fetching portfolio data, the scraper sometimes saves the wrong portfolio data instead of "NQ Värde & Momentum". This happens because of a race condition where the dropdown element hasn't fully loaded before the scraper attempts to interact with it.

## Root Cause

In `scraper.py`, the `get_portfolio_data()` method:
1. Navigates to `/portfolios` and waits for `domcontentloaded` + 3 seconds sleep (line 148-149)
2. Immediately tries to find and interact with the dropdown to select "NQ Värde & Momentum" (line 154-168)
3. If the dropdown isn't ready, the selection silently fails
4. The scraper then extracts data from whatever portfolio is currently displayed (often the wrong one)

The sleeps (`asyncio.sleep()`) are unreliable because they don't wait for actual DOM elements to be ready.

## Acceptance Criteria

1. **Reliable dropdown selection**: The scraper must wait for the dropdown to be fully rendered and interactive before attempting to select "NQ Värde & Momentum"
2. **Verification**: After selection, verify that the correct portfolio is actually displayed before extracting data
3. **Retry logic**: If the dropdown selection fails initially, implement retry logic with proper waiting
4. **Logging**: Add clear logging to diagnose if the wrong portfolio is being selected

## Technical Approach

- Use Playwright's `wait_for_selector()` with proper state options instead of fixed sleeps
- Verify dropdown selection by checking the current value after selection
- Add explicit waits for the table data to update after portfolio change
- Consider adding a verification step that asserts the correct portfolio is displayed
